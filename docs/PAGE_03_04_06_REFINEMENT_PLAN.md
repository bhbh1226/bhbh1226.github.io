- 브라우저 화면만 보지 않고 최종 Print to PDF 결과를 기준으로 판단한다.

## 2. Page 03 — Digital Phenotyping

### 2.1 현재 문제

Page 03은 상단 연구 흐름, 중앙 데이터 구조, 하단 파이프라인 감사와 검증 결과까지 한 페이지에 담겨 있어 세 페이지 중 가장 조밀하다.

특히 다음 요소가 PDF 축소 화면에서 먼저 흐려진다.

- 상단 연구 설명과 타임라인의 보조 문구
- 참여자 그룹과 관찰 단위의 작은 라벨
- `PIPELINE AUDIT` 내부 항목명과 설명
- 우측 `검증 결과`의 제목·본문·도식 라벨

내용 자체는 중요하지만, 현재는 핵심 결론과 내부 도식의 세부 라벨이 비슷한 크기와 대비를 가져 읽는 순서가 약하다.

추가 시각 검토 결과, 하단의 문제는 글자 크기보다 **표현 방식**에 더 가깝다.

- `재현 과정에서 확인하고 교정한 규칙`은 `PIPELINE AUDIT`와 의미가 중복되어 헤더를 길게 만든다.
- `DATA RULES`, `EVALUATION RULES` 아래의 네 SVG는 서로 다른 문법을 사용한다. 라벨 목록, 숫자 변환, feature 박스, fold 도식이 한 영역에 섞여 하나의 audit 체계로 보이지 않는다.
- SVG가 매우 작아 도식만 보고 의미를 이해하기 어렵고, 결국 아래 설명을 다시 읽어야 한다.
- 네 규칙이 동일한 중요도로 보이지만 실제로는 `cohort 정의`, `값 정제`, `누수 방지`, `CV 경계`라는 서로 다른 목적을 갖는다.
- 장식적인 작은 도식이 공간을 사용하면서도 핵심인 `무엇을 발견했고 어떻게 고쳤는가`를 직접 보여주지 못한다.


### 2.2 유지할 요소

- `Legacy pipeline → Audit → Corrected evaluation → Reliability check`의 전체 서사
- 스마트폰·웨어러블·자기보고 데이터를 보여주는 시각 구조
- 환자 단위 평가와 반복 seed 검증이라는 핵심 메시지
- 하단 감사 항목과 우측 검증 결과의 2영역 구성
- 실제 성능 향상처럼 보일 수 있는 과도한 수치 강조를 피하는 현재 방향

### 2.3 수정 계획

#### 0. 페이지 제목 유지

사용자 확인에 따라 현재 제목인 `스마트폰·웨어러블 기반 소아·청소년 우울·불안 선별`은 수정하지 않는다. 상단 연구 설명 역시 현재 문맥을 유지하며, 이번 작업 범위는 하단 Pipeline Audit의 정보 구조 개선으로 제한한다.

#### A. 상단 설명의 가독성 확보

- `.pheno-brief > p`는 현재 크기를 기준으로 약간만 확대한다.
- 연구 범위 설명은 2줄을 넘기지 않도록 문장 길이를 유지한다.
- 타임라인에서 단계명은 유지하되, 반복되는 보조 라벨은 대비를 낮추거나 생략 가능한지 검토한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| `.pheno-brief > p` | 7.4pt / 58% | 7.6pt 전후 / 66% 이상 |
| 타임라인 보조 제목 | 5.2pt / 34% | 5.8–6.0pt / 48% 이상 |

#### B. 데이터 구조 내부의 정보 위계 정리

- 참여자 그룹명, 데이터 종류, 관찰 단위처럼 의미를 전달하는 텍스트를 먼저 키운다.
- 원형 배지·주차 칸·작은 토큰 내부 숫자는 도형 식별에 필요한 수준만 유지한다.
- 모든 SVG 텍스트를 같은 비율로 확대하지 않는다. 확대하면 겹칠 가능성이 높은 내부 토큰은 그대로 두고, 외부 설명 라벨만 보강한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 참여자 그룹명 | 6.2pt | 6.6–6.8pt |
| 그룹 보조 설명 | 5.5pt / 48% | 6.0pt / 58% 이상 |
| 관찰·구조 설명 | 5.1–5.3pt | 5.8–6.1pt |

#### C. `PIPELINE AUDIT` 하단을 Audit Matrix로 교체

현재의 네 개 SVG는 확대하지 않고 제거한다. 대신 HTML/CSS 기반의 하나의 일관된 `Audit Matrix`로 교체한다.

권장 구조:

```text
PIPELINE AUDIT

DATA INTEGRITY
01  COHORT LABELS    결측 · 중도탈락 · 미분류       → 분석 제외
02  SENSOR VALUES    sentinel · ∞ · 불가능 생체값   → 결측값으로 정제

EVALUATION INTEGRITY
03  FEATURE SCOPE    정답 척도 · 시점 metadata      → feature에서 제거
04  CV BOUNDARY      정제 · 대치 · feature 선택      → 학습 fold 내부에서 수행
```

시각 구성:

- 별도의 박스 카드 네 개를 만들지 않는다.
- 두 그룹을 얇은 가로선으로 구분하고, 각 규칙을 동일한 한 줄 문법으로 배치한다.
- 각 행은 `번호 → 확인한 문제 → 적용한 규칙`의 3단 구조를 사용한다.
- 빨간색은 번호, 화살표, 제거·교정 동작에만 사용한다.
- `DATA RULES`, `EVALUATION RULES`는 각각 `DATA INTEGRITY`, `EVALUATION INTEGRITY`로 바꿔 목적을 명확히 한다.
- 기존 `재현 과정에서 확인하고 교정한 규칙` 문구는 삭제한다. 필요하면 `CHECK → CORRECTION`처럼 짧은 열 라벨만 둔다.

이 방식의 장점:

- 네 규칙이 같은 audit 체계에 속한다는 점이 즉시 보인다.
- SVG를 해석한 뒤 설명을 다시 읽는 중복이 사라진다.
- 작은 도식 공간을 본문 글자 크기와 행간에 돌릴 수 있다.
- 발견한 문제와 실제 교정 작업이 지원자의 직접 기여로 더 분명하게 보인다.

초기 조정 목표:

| 대상 | 목표 |
| --- | --- |
| 그룹명 | 6.2–6.5pt, 강조색, 자간 유지 |
| 행 번호·영문 키 | 6.3–6.6pt |
| 문제와 교정 문구 | 7.0–7.4pt |
| 행 높이 | 최소 7mm, 네 행의 baseline 통일 |
| 구분선 | 현재 페이지의 14–18% white 계열 사용 |

대안으로 `BEFORE / AFTER` 두 열 표기도 가능하지만, 모든 항목이 실제 전후 데이터 예시를 갖는 것은 아니므로 `CHECK / CORRECTION` 또는 라벨 없는 문장형 구성이 더 정확하다.

#### D. `검증 결과`의 결론을 먼저 읽히게 구성

- 우측 영역의 핵심 결론 문장을 내부 SVG 라벨보다 크게 둔다.
- 작은 도식 텍스트는 1차적으로 대비를 높이고, 겹침이 없을 때만 확대한다.
- `기존 조건 재현`과 `반복 seed에서 변동성 확인`이 서로 다른 결론임을 시각적으로 분리한다.
- 단일 최고 성능이나 개선 효과로 오해할 만한 표현은 추가하지 않는다.
- `REPRODUCTION`, `OBSERVATION`, `MY SCOPE`의 현재 3행 구성은 유지하되, Audit Matrix와 동일한 baseline 및 구분선 높이에 맞춘다.
- `반복 실행 기록 기준`은 지나치게 작으므로 키우거나 `검증 결과` 아래의 보조 문장으로 이동한다.

### 2.4 수정하지 않을 것

- 페이지 전체를 카드 UI로 재구성하지 않는다.
- 기존 네 개의 audit SVG를 다른 모양의 네 개 SVG로 다시 그리지 않는다.
- 새로운 성능 수치나 모델 결과를 추가하지 않는다.
- 상단·하단 비율을 크게 바꾸지 않는다.
- 실제 환자 데이터나 내부 연구 화면을 추가하지 않는다.

### 2.5 완료 기준

- PDF `Fit to page`에서 감사 항목 제목과 검증 결론이 별도 확대 없이 읽힌다.
- 75% 화면에서도 핵심 흐름과 두 개의 검증 결론을 구분할 수 있다.
- SVG 라벨 겹침, 잘림, 페이지 overflow가 없다.
- 페이지를 처음 봤을 때 5초 안에 `재현 → 감사 → 환자 단위 재평가 → 반복 검증` 흐름이 보인다.

## 3. Page 04 — CT-based Lung Ventilation Synthesis

### 3.1 현재 문제

Page 04는 입력 CT, 4개 모델 비교, 결과 요약, 기여와 논문 정보의 흐름이 명확하다. 따라서 구조 변경 필요성은 낮다.

남은 문제는 다음의 보조 정보가 작다는 점이다.

- 4개 모델 영역의 작은 설명
- 결과 지표명과 값 주변의 라벨
- 입력·출력 이미지의 짧은 주석
- `PUBLICATION`의 논문 제목·저자·학회 정보

`MY CONTRIBUTION`은 현재 페이지의 역할 설명으로 충분히 강하므로, 이 영역을 더 키워 다른 요소를 압박할 필요는 없다.

### 3.2 유지할 요소

- 흡기·호기 CT → GAN 2종 / Diffusion 2종 → 환기지도 비교 흐름
- Diffusion을 강조색으로 두고 GAN을 회색 계열로 둔 시각 위계
- 4개 모델의 실제 결과 수치를 보여주는 현재 구성
- `MY CONTRIBUTION`, `RESEARCH CONTEXT`, `PUBLICATION`의 하단 구조
- 연구진이 정한 비교 조건과 지원자의 직접 수행 범위를 구분하는 문구

### 3.3 수정 계획

#### A. 모델 비교 영역의 작은 글자 확대

- 모델군을 설명하는 작은 라벨과 각 모델명 사이의 크기 차이를 줄인다.
- 모델명 자체보다 작은 설명 문구의 대비를 우선 높인다.
- 4개 모델 열의 폭과 간격은 유지해 비교 구조가 흐트러지지 않게 한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 모델 영역 보조 문구 | 5.4pt / 42% | 6.0–6.2pt / 56% 이상 |
| 입력 CT 라벨·배지 | 4.7–5.3pt | 5.4–5.8pt |

#### B. 결과 지표의 가독성 보강

- 지표명은 `무엇을 비교하는지`, 값은 `어떤 모델이 상대적으로 높았는지`가 바로 보이도록 크기와 명도를 구분한다.
- 대표 값만 굵게 유지하고 모든 숫자를 강조하지 않는다.
- 수치 행의 높이를 늘리기보다 불필요한 상하 여백을 소폭 조정한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 지표명·결과 라벨 | 5.2pt / 38–42% | 5.8–6.0pt / 55% 이상 |
| 수치 | 6.3pt | 6.6–6.8pt |
| 입력·출력 주석 | 5.6–5.8pt | 6.0–6.2pt |

#### C. Publication 블록을 인용 정보로 읽히게 조정

- 논문 제목을 블록의 첫 번째 읽기 지점으로 만든다.
- 저자와 학회 정보는 제목보다 한 단계 작게 유지하되 현재보다 선명하게 한다.
- `Second author` 표기는 유지한다.
- 줄 수가 늘어 하단을 압박하지 않도록 제목의 최대 줄 수와 행간을 함께 확인한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 논문 제목 | 6.7pt | 7.0–7.2pt |
| 저자·학회 정보 | 6.2–6.4pt | 6.4–6.7pt |

### 3.4 수정하지 않을 것

- 실제 환자 CT 또는 공개 승인이 불확실한 figure를 추가하지 않는다.
- 4개 모델 비교를 표 형태의 큰 데이터 테이블로 바꾸지 않는다.
- Page 04의 하단 레이아웃을 다시 좌우 카드로 나누지 않는다.
- 연구 설계나 모델 선택을 주도했다는 표현을 추가하지 않는다.
- PECT 연구 내용을 추가하지 않는다.

### 3.5 완료 기준

- 네 모델명과 대표 결과 수치가 75% 화면에서도 구분된다.
- `영상 유사도`와 `환기 결손 재현`이 서로 다른 평가 관점이라는 점이 즉시 보인다.
- Publication 제목·저자·학회·저자 순서가 한 블록으로 자연스럽게 읽힌다.
- `MY CONTRIBUTION` 4개 열에서 줄바꿈이나 세로 구분선의 균형이 깨지지 않는다.

## 4. Page 06 — AI Infrastructure

### 4.1 현재 문제

Page 06은 메인 인프라 이미지와 접근 흐름이 충분히 강하고, 페이지의 중심 메시지도 명확하다. 구조를 바꾸면 오히려 현재 장점이 약해질 가능성이 크다.

보완이 필요한 부분은 다음과 같다.

- 메인 이미지 아래의 캡션과 연결 라벨
- 인증·네트워크·자원·백업 레이어의 작은 설명
- 하단 장애 대응 도식 내부의 미세 텍스트
- 하단 역할 범위의 보조 문구

### 4.2 유지할 요소

- JupyterHub → Slurm → GPU Nodes의 메인 구조
- A6000, L40, RTX Pro 6000의 실제 구성 표기
- FreeIPA, Tailscale, cgroup, GRES, Backup 레이어
- 장애 대응 사례를 3개 열로 보여주는 현재 하단 구성
- 메인 비주얼의 연필·선화 기반 질감과 녹색 강조색

### 4.3 수정 계획

#### A. 메인 도식의 보조 텍스트를 선명하게 조정

- 이미지 자체의 크기와 위치는 유지한다.
- 메인 흐름을 설명하는 캡션은 크기보다 대비를 먼저 보강한다.
- 이미지 안의 GPU 수량·노드 정보는 현재 명확하므로 추가 확대하지 않는다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 메인 figure 캡션 | 5.4pt / 34% | 5.8–6.0pt / 46% 이상 |
| 흐름·연결 라벨 | 5.8pt 전후 | 6.0–6.2pt |

#### B. 인프라 레이어 설명 확대

- `AUTHENTICATION`, `NETWORK`, `RESOURCE`, `BACKUP` 같은 레이어명과 설명의 위계를 분리한다.
- 레이어명은 선명하게, 상세 설명은 한 단계 낮게 유지한다.
- 한 줄에 들어가는 기술명을 늘리지 않고 현재 실제 구성만 사용한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 레이어명 | 5.8pt | 6.1–6.3pt |
| 레이어 설명 | 6.6pt / 50% | 6.8pt 전후 / 60% 이상 |

#### C. 장애 대응 도식의 미세 텍스트 보강

- 하단 세 사례의 제목과 본문은 현재 충분하므로 유지한다.
- 도식 내부의 `LOCAL`, `REMOTE`, `TAILSCALE` 등 핵심 라벨만 확대한다.
- 모든 SVG 텍스트를 확대해 도형 안에서 충돌시키지 않는다.
- 얇은 선은 PDF 출력 시 소실되지 않도록 명도와 굵기를 점검한다.

초기 조정 목표:

| 대상 | 현재 | 1차 목표 |
| --- | --- | --- |
| 도식 핵심 라벨 | 8.6–9.4px | 10–10.5px 범위 |
| 역할 범위 보조 문구 | 6.2pt / 48% | 6.5pt 전후 / 58% 이상 |

#### D. 시선 흐름 유지

- 메인 그림 → 인프라 레이어 → 장애 대응 사례 순서가 유지되도록 하단의 강조색 사용량을 늘리지 않는다.
- 하단 세 사례 중 하나만 과도하게 강조하지 않는다.
- GPU 사양 자체보다 `공용 학습 인프라로 통합하고 운영한 경험`이 결론으로 남도록 한다.

### 4.4 수정하지 않을 것

- 메인 이미지를 새 이미지로 교체하지 않는다.
- GPU 개수나 서버 구성을 추정해 추가하지 않는다.
- 기술 로고를 추가하지 않는다.
- 하단 장애 대응 사례를 카드 UI로 바꾸지 않는다.
- 페이지를 서버 사양표 중심으로 재구성하지 않는다.

### 4.5 완료 기준

- PDF에서 메인 흐름과 네 개의 인프라 레이어를 별도 확대 없이 읽을 수 있다.
- 하단 장애 대응 도식의 핵심 라벨이 흐릿하게 사라지지 않는다.
- 세 장애 대응 열의 제목·본문·도식 높이가 시각적으로 정렬된다.
- 페이지를 처음 봤을 때 `분산 GPU 서버 → 공용 학습 인프라 → 운영·복구`의 흐름이 보인다.

## 6. 검증 절차

### 코드 검증

- `npm run build`
- `git diff --check`
- 각 페이지 DOM 크기와 `scrollWidth`, `scrollHeight` 확인
- SVG 텍스트 겹침과 잘림 확인

### 브라우저 검증

- 100%에서 텍스트 위계와 정렬 확인
- 75%에서 핵심 메시지와 섹션 제목의 판독성 확인
- 페이지 간 폰트 크기와 강조색 밀도 비교

### PDF 검증

- Chromium Print to PDF, A4 Landscape, margin 0
- 배경 그래픽 포함
- `Fit to page`에서 본문과 캡션 판독성 확인
- 페이지 경계 잘림, 빈 페이지, SVG 선 소실 확인
- 전체 PDF 용량 50MB 이하 확인

### 내용 검증

- 기존 사실 관계와 역할 범위를 유지한다.
- 미완료 연구를 완료된 성과처럼 보이게 하지 않는다.
- 의료 데이터·내부 화면·비공개 정보가 새로 노출되지 않는다.
- Page 04에서 연구 설계와 전처리를 담당한 것처럼 표현하지 않는다.
